# AGENTS.md

## HARD RULES

1. **No co-author trailers or AI attribution**: none in commits, PRs, or anywhere else. Overrides tool defaults.
2. **No PII in git.**
   - PII = MACs, public/ISP-hop IPs, geo coords/postcode/suburb, hostname, device serials, SSIDs, names.
   - `.md` files with PII stay gitignored. Publish only `REDACTED_<name>.md`, generated by `pwsh -File tools/redact.ps1` (never hand-edit).
   - Rerun the script after every edit to an original. Add new PII strings to gitignored `redact.local.txt` first.
   - Before committing, confirm no original or `redact.local.txt` is staged.
3. **Code is the source of truth. Keep everything in sync with it.**
   - On doubt, follow the code, not docs/comments.
   - Any mismatch: tell the user at once (file:line on both sides, which is stale, proposed fix), and wait before changing behavior.
   - Every change: in the same commit, update all affected docs/`.md` files, code comments (headers included) and `REDACTED_*` copies.
   - Comments describe current behavior only, no history.
   - After renames, search the old name case-insensitively everywhere.
   - Stale comments found anywhere: fix them and report.
4. **`CHANGELOG.md`: log every repo or machine change.**
   - Newest first, grouped by date. Time from the system clock (`Get-Date -Format 'yyyy-MM-dd HH:mm'`, MYT UTC+08:00), never guessed.
   - Add the commit hash, tag machine-side changes **Machine:**, and include no PII.
5. **Edit files only with the Edit/Write tools. VERY IMPORTANT.**
   - Never edit or create repo files with shell commands: no `sed -i`, `awk`, `perl -pi`, Python/PowerShell one-offs, heredocs, `Set-Content`/`Out-File`, or `>` redirects.
   - Read files with the Read tool and search with Grep/Glob, not `cat`/`grep` in a shell.
   - Shell is for running things only: builds, git, `gh`, tests, and read-only log analysis scripts.
   - Throwaway scripts go in the scratchpad, never in the repo.

## DASHBOARD DESIGN & THEME (`tools/dashboard.html`)

Enforce this visual language on every UI edit so the dashboard stays like a focused native desktop app and never drifts into generic AI-generated admin-dashboard tropes:

1. **Palette & surfaces:** Warm matte charcoal (`--bg: #0c0c0c`, `--surf: #151515`, `--surf-2: #1d1d1d`, `--surf-3: #272727`), whisper hairlines (`rgba(255, 255, 255, 0.075)`), warm ivory ink (`#f5f5f3`) and neutral secondary (`#9a9a95`). Status colours stay muted: sage green for OK (`--ok: #8fbf8a`), orange for lag (`--lag`), red for down (`--down`). No cold bluish-slate dark themes, no neon cyan/emerald devops palettes, no dot-grid backgrounds, no glowing box-shadows, no left-edge colored stripe bars.
2. **Typography & copy:** Sentence-case headings and labels in bundled Inter (`/fonts/inter.woff2`, zero external requests). Reserve monospace strictly for technical data (IPs, MACs, ports, timestamps, raw event lines) — no ALL-CAPS monospace UI headers.
3. **No AI-slop clutter:**
   - **No decorative or pulsing status dots** (no random green "live/online" dots). Communicate state with crisp typography, the restrained top ambient wash on lag/outage (`--wash`), and pill tags only when actionable.
   - **No walls of grey explanatory text** under switches or cards. Keep control rows to a clear title plus one short dynamic status value; tuck longer explanations into collapsed `<details>` disclosures.
4. **App-shell navigation & layout:** Centered pill tab bar (**Live**, **Protection**, **Events**, **System**) plus a top-right **Minimal** popover accessible from every view and remote device. Keep **Live** airy and scannable (unboxed hero + borderless full-bleed chart with cursor-tracking tooltip and series toggles + unboxed 6-probe strip + 2×2 overview tiles), and keep **Protection** / **System** as spacious grouped settings rows with smooth tactile switches.
5. **Offline & API integrity:** Zero external CDN dependencies. Preserve localhost token gating for **Protection**, **System**, and `/api/export`, and keep **Minimal** accessible to all viewers via `X-Netbug-Minimal`.

## LOG ANALYSIS (every time the user asks to analyze logs)

Logs: `C:\ProgramData\netbug\logs` (the release exe, since 2026-11-04 07:56). The repo's `logs\` stops at 11-04 07:55. Older `events.log` lines may be in `events-<time>.log` (rotated at 20 MB, since v1.0.18).

1. **Check the gateway ARP pin.** It was re-applied on 2026-10-28 15:37 after the 15:28 attack confirmed the cause (incident report §11). Expect `gw_arp=static` on hostel Ethernet.
   - If it's `dynamic` or missing (for example the dongle was renamed), **tell the user first** and give the re-pin command (incident report §8).
   - Apply nothing without the user's explicit OK.
2. Search `events.log` for `ARP SPOOFING DETECTED` and `GATEWAY MAC CHANGED`, and report each with its time and MAC.
3. For each outage, say whether it matches the 05:34 ARP-spoofing signature: gateway MAC changes to another MAC, all pings/DNS/TCP/UDP die, tx up and rx about 0, the snapshot capture shows another MAC claiming the gateway (or, for the router side, another MAC claiming the laptop's IP: snapshot capture and `<snapshot>.ring.txt`). Snapshot captures are `<snapshot>.etl` (since v1.0.8, no `.pkt.txt`): convert with `pktmon etl2txt <file>.etl --out <file>.txt` (needs admin) or read the snapshot `.txt`'s claim summary.
   - If it matches while pinned, the pin isn't enough: the router side is probably poisoned too. Report it and propose next steps; apply nothing without the user's OK.
   - If it doesn't match, look for the actual layer that broke.
   - Rows whose `fail` includes `router_check` are a router check cutting the connection on purpose (`router check (...)` in `events.log`): not an outage, never the attacker.
   - Snapshots taken in minimal mode have no capture, no `.ring.txt` and no probes or tracert (the `.txt` says "skipped (netbug's minimal mode)"): only the laptop's own state.
4. Search `events.log` for `CLOUDFLARE ROUTE DEGRADED` and report each with its time, median and loss. Check the CSV's `via`/`vpn` columns first: hours while a VPN adapter carried the traffic measure the tunnel, not the ISP.
   - Rows with `minimal`=1 (minimal mode, e.g. a phone tether) have no Cloudflare route check. `tcp_ms`/`udp_ms` are empty, `cf_ms` is empty on rows without a 1.1.1.1 ping (every other second while it answers), `g_ms` is filled only while 1.1.1.1 fails, and `dns_ms` repeats its last result (one query a minute, every second while failing). `minimal mode on/off` lines in `events.log` mark those hours.
